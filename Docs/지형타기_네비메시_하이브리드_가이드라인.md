# 지형 타기 구현 가이드라인 — COL 메시 레이캐스트 (Phase 1)

> 작성일: 2026-04-05
> 목적: `MovementComponent`의 `groundY = 5.f` 하드코딩 → COL 메시 기반 실제 지형 높이 판정으로 교체
> 대상 맵: ExamStadium (COL 메시 2개: Ground, Wall)

---

## 0. 현재 상태 요약

### 해결할 문제
```cpp
// MovementComponent.cpp:321-332 — 현재 코드
if (currentPos.y <= _moveDesc.groundY && _velocity.y <= 0.f)  // groundY = 5.f 상수!
{
    currentPos.y = _moveDesc.groundY;
    // ...
}
```
→ 맵 전체가 무조건 Y=5 평면. 경사/계단/다리 등 대응 불가.

### 사용할 COL 메시 (이미 meshbin 변환 완료)
```
Client/Bin/Resources/StaticMesh/ExamStadium/Meshes/
├── SM_ENV_TCHEXA_ArenaGround_A_COL.meshbin  (58 KB, 바닥)
└── SM_ENV_TCHEXA_ArenaWall_A_COL.meshbin    (78 KB, 벽)
```

### 데이터 흐름 요약
```
meshbin 파일
  → Model_BinaryLoader::Load()
    → FModelBinaryData { meshes[].vertices[], meshes[].indices[] }
      → FMeshVertexRaw { px, py, pz, nx, ny, nz, ... }
```

`FMeshVertexRaw.px/py/pz`에 정점 위치가 이미 다 들어있다!
지금은 이걸 `VTXMESH`로 변환해 **GPU 버퍼에만** 올리고 CPU 원본은 버리고 있음.

### 1-2. Mesh.cpp — Create_Buffers(VTXMESH) 수정

기존 `Create_Buffers` 함수의 **맨 끝**에 CPU 캐싱 코드를 추가한다.
(GPU 버퍼 생성 코드는 전혀 건드리지 않는다)

```cpp
HRESULT Mesh::Create_Buffers(const vector<VTXMESH>& vertices, const vector<uint32>& indices)
{
    // ─── 기존 GPU 버퍼 생성 코드 전부 그대로 유지 ───
    _numVertexBuffers = 1;
    _numVertices = static_cast<uint32>(vertices.size());
    _vertexStride = sizeof(VTXMESH);
    _numIndices = static_cast<uint32>(indices.size());
    _indexStride = sizeof(uint32);
    _primitiveType = D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST;

    // ... vertex buffer, index buffer 생성 코드 그대로 ...

    // [추가] CPU 데이터 캐싱 — 레이캐스트용으로 position만 복사
    if (_keepCPUData)
    {
        _cpuPositions.resize(vertices.size());
        for (size_t i = 0; i < vertices.size(); ++i)
```

```cpp
    _meshes.clear();
    _numMeshes = static_cast<uint32>(data.meshes.size());

    for (const FMeshBinaryData& srcMesh : data.meshes)
    {
        vector<VTXMESH> vertices;

            vertex.tangent = Vec3::TransformNormal(tan, _preLocalTransformMatrix);

            vertices.push_back(vertex);
```

### 2-4. Model.cpp — Raycast 구현

```cpp
// [추가] 모든 메시 삼각형을 순회하며 Ray-Triangle 교차 검사
//        SimpleMath의 Ray::Intersects()를 사용하므로 코드가 아주 깔끔해집니다.
bool Model::Raycast(const Ray& ray, float& outDist, Vec3& outHitPoint) const
{
    float closestDist = FLT_MAX;
    bool hit = false;

    for (const auto& mesh : _meshes)
    {
        const auto& positions = mesh->Get_CPUPositions();
        const auto& indices = mesh->Get_CPUIndices();

        // CPU 데이터가 없으면 스킵 (_keepCPUData가 false였던 일반 렌더링 메시)
        if (positions.empty() || indices.empty())
            continue;

        // 삼각형 단위로 순회 (인덱스 3개 = 삼각형 1개)
        for (size_t i = 0; i + 2 < indices.size(); i += 3)
        {
            const Vec3& v0 = positions[indices[i]];
            const Vec3& v1 = positions[indices[i + 1]];
            const Vec3& v2 = positions[indices[i + 2]];

            float dist = 0.f;

            // SimpleMath::Ray 내장 교차 검사! (XMLoadFloat3 변환 따위 필요 없음)
            if (ray.Intersects(v0, v1, v2, dist))
            {
                if (dist >= 0.f && dist < closestDist)
                {
                    closestDist = dist;
                    hit = true;
                }
            }
        }
    }

    if (hit)
    {
        outDist = closestDist;
        // 히트 위치 = Ray 원점 + Ray 방향 * 거리
        outHitPoint = ray.position + ray.direction * closestDist;
    }

    return hit;
}
```

## 3단계: COL 메시를 렌더링 없이 로드

COL 메시는 **보이지 않는 충돌 전용 데이터**이므로, 렌더하지 않고 CPU 데이터만 갖고 있으면 된다.

## 4단계: MovementComponent에서 레이캐스트로 바닥 판정

### 4-1. MovementComponent.h에 추가

### 4-2. MovementComponent.cpp — Apply_Movement 전체 교체

```cpp
void MovementComponent::Apply_Movement(float timeDelta, Shared<Transform> transform)
{
    transform->Add_WorldOffset(_velocity * timeDelta);

    Vec3 currentPos = transform->Get_WorldPosition();

    // [변경] 기존 groundY 하드코딩 제거 → COL 메시 레이캐스트 기반 바닥 판정
    if (_velocity.y <= 0.f)  // 하강 중일 때만 바닥 체크
    {
        bool foundGround = false;
        
        // 발밑 판정을 위해 현재 캐릭터 위치에서 조금 위부터 아래 방향 지정
        Vec3 rayOrigin = currentPos + Vec3(0.f, 0.5f, 0.f); 
        Vec3 rayDir = Vec3(0.f, -1.f, 0.f);
        Ray downRay(rayOrigin, rayDir);

        float bestHitHeight = -FLT_MAX; // 가장 높은 바닥을 찾기 위함
        float hitDist = 0.f;
        Vec3 hitPoint;

        // 로드된 모든 COL 모델에 대해 레이캐스트 실행
        for (const auto& colModel : _groundCollisionModels)
        {
            if (colModel && colModel->Raycast(downRay, hitDist, hitPoint))
            {
                foundGround = true;
                // 레이에 맞은 바닥면 중 가장 높은(Y값이 큰) 면 위에 서도록 함
                if (hitPoint.y > bestHitHeight)
                {
                    bestHitHeight = hitPoint.y;
                }
            }
        }

        // 바닥에 닿았으면 위치 보정
        // 여유값 0.1f: 경사면에서 미세하게 떠있는 현상 방지
        if (foundGround && currentPos.y <= bestHitHeight + 0.1f)
        {
            currentPos.y = bestHitHeight;
            transform->Set_LocalPosition(currentPos);

            _velocity.y = 0.f;
            _onGround = true;
            _canDoubleJump = false;
        }
        else if (!foundGround && currentPos.y <= _moveDesc.groundY && _velocity.y <= 0.f)
        {
            // [폴백] 근처 바닥이 아예 뚫려있거나 못 찾았으면 최후의 수단으로 임시 바닥 보정
            currentPos.y = _moveDesc.groundY;
            transform->Set_LocalPosition(currentPos);
            _velocity.y = 0.f;
            _onGround = true;
            _canDoubleJump = false;
        }
        else
        {
            _onGround = false;
        }
    }
    else
    {
        _onGround = false;
    }
}
```

## 5. 작업 순서 체크리스트

## 7. 트러블슈팅 예상 문제

### 7-1. 캐릭터가 바닥을 뚫고 떨어진다
- **원인**: Ray가 삼각형 아래쪽에서 시작하고 있음
- **해결**: `rayOrigin`의 Y 오프셋을 0.5f → 1.0f로 올려본다.

### 7-2. 경사면에서 캐릭터가 덜덜 떤다
- **원인**: 매 프레임 Y가 급변하면서 onGround가 true/false를 반복
- **해결**: `groundHeight + 0.1f` 임계값을 0.2f ~ 0.3f로 높여본다.

### 7-3. 레이캐스트 결과가 항상 miss다
- **원인 1**: COL 메시의 좌표계와 게임 좌표계가 다름 (스케일, Y-up/Z-up)
- **확인 방법**: `Raycast` 내부에서 `positions[0]`을 로그로 찍어보고, 캐릭터 위치와 비교
- **원인 2**: `_preLocalTransformMatrix`가 `Matrix::Identity`가 아님
- **해결**: COL 메시 로드 시 `Matrix::Identity`를 사용하되, 필요하면 스케일 `Matrix::CreateScale(0.01f)` 등

### 7-4. COL 메시 좌표가 너무 크거나 작다
- **확인**: `_cpuPositions[0]`의 값을 로그로 찍어본다
- ExamStadium의 meshbin은 이미 AssimpTool 변환(pskx→gltf→meshbin) 과정에서 스케일이 적용되어 있을 수 있음
- Level JSON의 `unit_scale=0.01`과 메시 자체의 스케일이 일치하는지 확인 필요

### 7-5. 성능이 느리다
- ExamStadium의 Ground COL은 58KB로 작아서 브루트포스로 충분
- 만약 KonohaVillage03에서도 이 방식을 쓸 거면 BVH(Bounding Volume Hierarchy) 추가 필요
- → 이건 Phase 2에서 Recast로 대체하면 자동 해결됨

## 8. 향후 확장 (Phase 2 — Recast, 나중에)

Phase 1이 완료되면 다음과 같은 확장이 가능하다:

1. **Recast로 NavMesh 빌드**: `_cpuPositions` + `_cpuIndices`를 Recast에 넣으면 NavMesh가 생성됨
2. **A* 길찾기**: NavMesh 폴리곤 위에서 자체 A* 구현 (쥬신 수업의 Cell 방식 응용)
3. **Wall COL 처리**: 현재는 Ground만 로드했지만, Wall COL도 같은 방식으로 로드하여 벽 밀어내기에 활용 가능
4. **여러 COL 메시 합치기**: Ground + Wall + Bridge 등 여러 COL을 하나의 Model에 합쳐서 레이캐스트
